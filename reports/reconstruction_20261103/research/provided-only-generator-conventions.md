# Generator conventions: external method research, supplied-only candidates

Observed 2026-11-03. This review uses public source code, public documentation and the command/schema metadata of one archived SHOP 17.17.0 case to understand methods. It does not add downloaded solver values, public commitment labels, pseudo-labels or external numerical lookups to any candidate. All current candidate training and inference still use only the original competition files and locally derived features. Root owns terminal water-value conversion research; physics_trick owns the separate numerical hydraulic comparison.

The strongest remaining structural discrepancy is that our LP uses initial reservoir heads throughout the horizon, while SHOP performs multiple full iterations with head optimization. The exact archived case runs five full iterations before locking commitment. The known initial/terminal time conventions and free initial generator state do not reveal a fresh indexing defect. Earlier simple head-update ablations failed; this evidence motivates a faithful coupled iteration only if its physical consistency improves, not another arbitrary postprocessing adjustment.

## What is established

| Convention | Evidence | Consequence for the supplied-only model |
| --- | --- | --- |
| 168 hourly decisions and an end boundary | Supplied dataset documentation places initial volume at the start and terminal water value at start+7 days. Public code loads 169 timestamps inclusively but uses the last as `endtime`, giving 168 intervals. Archived case1 spans Jan1 00:00 to Jan8 00:00 UTC. | Keep the current 168 rows and start+7-day terminal lookup. The final input timestamp is not a 169th decision. |
| Five full, five incremental iterations in the exact release | The archived17.17 case1 command list is `set universal_mip off`, `start sim 5`, `set code incremental`, `start sim 5`, `set simtimestep 1`, `start shopsim gen_mw_result 3600`. | A single initial-head LP does not reproduce this optimization process. |
| Full iterations choose commitment; incremental iterations refine it | The current [set code documentation](https://docs.shop.sintef.energy/commands/set_code.html) says full mode determines commitment, head optimization is on by default and requires two full iterations to activate. | Reconstructing a full-mode fixed point is more relevant to commitment than matching subsequent simulator discharge. Current documentation is18.4.1; the exact17.17 archive establishes the commands but not every internal default. |
| No-MIP cutoff uses discharge relative to physical minimum | The [generator documentation](https://docs.shop.sintef.energy/objects/generator/generator.html) describes the default off cutoff as `q < .5*Qmin`; binary-MIP periods follow their binary state. | Thresholding a relaxed commitment variable at .5 is not generally the same rule. Existing LP `q/Qmin` and fractional-state features remain distinct coordinates. |
| Simulation is a subsequent physical evaluation | The [SHOPSIM command documentation](https://docs.shop.sintef.energy/commands/start_shopsim.html) distinguishes production-driven and discharge-driven modes. Exact17.17 case1 uses `gen_mw_result`; the newer18.4 source currently selects `gen_m3s_result`. | Do not infer commitment changes from simulation-only differences or silently replace the archived mode with the newer source's setting. |
| Initial generator state is unspecified in supplied topology | No `initial_state`, production history, availability or minimum up/down-time field appears in the supplied YAML or either reviewed generation routine. The public formulation report explicitly omits the first transition cost when initial state is absent. | Our free first-period generator boundary is consistent with available evidence. Do not invent a previous-day commitment input. Opaque archived binary input state has not been decoded. |
| No supported currency conversion correction | Generic SHOP attributes label startup costs NOK, but public topology preparation describes river costs in EUR and generation code directly supplies EUR prices and raw YAML startup costs; the local `currency='EUR'` variable does not execute a conversion command. | There is no evidence for multiplying or dividing costs by an exchange rate. Preserve supplied numerical values. |

## Source versions must remain distinct

The supplied PDF identifies v5_2026_6 and SHOP17.17.0. The [June source](https://gitlab.sintef.no/energy/open-modelling-tools/open-datasets/tokke-vinje-watercourse/-/blob/5fca23ebb1fc57b5a29c6f650be0efd21e74713c/scripts/SHOP_multiprocessing_run.py) is a version-comparison harness: it initializes reservoir head, performs3+3 iterations, uses tactical head limits with cost1000, and its Mixed setting activates MIP for the first36 hours. Its displayed CSV export is an aggregate diagnostic, not the competition label producer.

The [October source](https://gitlab.sintef.no/energy/open-modelling-tools/open-datasets/tokke-vinje-watercourse/-/blob/11b8d7c6e30c81c878e8a80540721d817b47a0c7/scripts/multiprocessing_dataset_generation.py) identifies SHOP18.4, initializes volume, performs5+5 iterations, uses hard minimum-volume fields, and its Mixed setting runs three relaxed full iterations followed by two MIP full iterations. It disables reservoir penalties, leaves maximum-reservoir constraints empty, and now uses discharge-driven SHOPSIM. These differences mean neither file can be presented as the exact17.17 competition generator.

In the October source, `solver_production`, `solver_committed_fraction` and `committed_out` are read into CSV columns immediately after full mode, before incremental mode and SHOPSIM. Its output JSON is dumped after those later operations. The exact17.17 archive contains final JSON plus opaque binary inputs and no generation source. Therefore the JSON hydraulic fields and the CSV hydraulic fields should not be assumed to describe the same optimization stage. Whether the exact17.17 CSV extraction used this same location is not established by source alone.

No unit-order defect was found: the local exported predictions use explicit generator names, original mapping columns and case/date/hour alignment, rather than the alphabetical iteration order of the archive's JSON objects. No inference input should depend on serialized object order.

## Reproducible evidence and limits

`artifacts/provided-only-generator-conventions-001/manifest.json` pins reviewed source hashes, original topology, documentation, archived JSON metadata, exact command list and the archive/member identity. It records the small safe binary-header inspection; no binary deserialization or external code execution occurred. The archive input member is proprietary binary after Zstandard decompression, so unset states, H1 flags and penalty settings inside it remain unproven. External numerical output schedules were not used by this review to fit or choose a candidate. The independent numerical hydraulic research is recorded separately.

The next useful diagnostic is a physically consistent supplied-only full-mode iteration with finite-horizon head updates, bounded feasible curves and explicit convergence checks, compared on the already frozen small cases. Root and physics_trick own that work. Mere duplication of a five-iteration count, or matching final SHOPSIM outputs, would not establish fidelity.
