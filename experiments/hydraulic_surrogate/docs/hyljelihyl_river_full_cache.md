# Full C-only river cache

This frozen preparation applies the accepted persistent-worker execution contract to all 3,647 input cases. It does not decode targets or authorize a learned model. The mathematics, solver options, 20-second per-call limit, 62 feature formulas and exact 664-column prefix are unchanged from the audited pilot. The strict `add_river_cost_features` API is unchanged.

The supplied Hyljelihyl marginal river curve is integrated over finite step widths and an unbounded final segment. Its 0.26 Mm³ reservoir is separated from the remaining 307 Mm³ Vinje pool. Each arm uses its own downstream mapping in the economic-margin features. The two bypasses retain the explicit joint 1,000 m³/s cap needed for projection into the original model. These are the frozen v2 approximation, not a reconstruction of all SHOP commands.

The no-solve preflight reconstructs all original inputs byte for byte, checks equal local terminal values, prepares split inputs/networks and seals their matrix signatures and file hashes. Both child processes verify the source/protocol/environment and externally hashed preflight, then recheck each case's inputs and original continuous control before solving. Fresh solver objects are built for every call.

Two distinct persistent single-thread workers process every new case, one in ascending order and one in a fixed seed-4173 permutation. Both complete result arrays, native arrays, primal/dual arrays and float32 features must have identical shapes, dtypes and literal bytes. This proof explicitly allows process persistence; it does not claim a new process for every case. The 59 audited pilot cases are copied without modifying any payload or proof, with separate import receipts. Their external audit includes exact agreement with all 36 canonical fresh-process results.

Every newly solved case receives an immutable `cases/case_N/complete.json` only after both physical and replay checks pass. The receipt pins all payloads, input record, worker identities and execution lineage. The aggregate feature NPZ is assembled only when all 3,647 receipts exist. A later independent physical audit of the complete cache is mandatory before the compact 726-column loader can load features.

Entry requires at least 30% pressure-derived free memory, at least 3 GiB measured headroom and no swapout growth between entry readings. Workers and coordinator request a drain between cases below 20% free memory, below 3 GiB headroom, on swapout growth or after a failed case. Each worker must remain below 2 GiB peak RSS. No allocation probe is used. On coordinator exceptions, a stop marker requests finishing the active calls and the parent joins both workers. If child exit cannot be proved within 60 seconds, status becomes `blocked_active_children` and automatic resume is prohibited. No process signals or forced termination are used.

Resume requires an externally hashed same-protocol incomplete manifest, verified child exit, byte-intact complete receipts and no retained failed case proof. It preserves old phase outputs and recomputes only cases without finalized receipts in a new phase. A previous operational stop marker is archived under the prior manifest hash; immutable receipts and their payloads are never changed. Native failure, physical-gate failure or replay failure is retained and is not automatically retried. There is no LP substitution, missing-row fill or partial-cache loader.

The pilot took 22.95 seconds for two 59-case worker passes, with approximately 0.257 seconds per solve and 332 MB peak worker RSS. A linear solve-only estimate for the remaining 3,588 cases is about 15.4 minutes per worker; hashing, receipt publication, feature compression and hard-case tails add overhead. This estimate is operational planning, not a runtime guarantee. Progress reports count fresh completions separately from imported cases.

Preparation commands use `.venv-ml/bin/python` through offline `uv run`. Freeze with `scripts/build_hyljelihyl_river_cache.py --freeze-protocol`; run `--preflight --protocol-sha256 SHA --run-id ID`. Actual execution additionally requires externally pinned input-preflight and independent-source-audit manifests. Full execution remains subject to the root agent's explicit authorization after those gates.
