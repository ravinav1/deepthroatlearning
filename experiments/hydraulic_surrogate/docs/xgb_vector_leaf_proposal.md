# Shared vector-leaf trees: proposed learned branch

The next distinct learned-model hypothesis is to share tree partitions across all fourteen generators while retaining a separate value for every output in each leaf. Common water, price and plant constraints may make shared partitions useful. The main falsification risk is underfitting generators with different economics or commitment boundaries.

The experiment inventory contains independent LightGBM/XGBoost models, CatBoost specialists, MLP/TCN, latent/CRF corrections, pooled pairwise/BCE residuals, linear leaves and generator offsets. A search of the recorded experiments and source found no previous `multi_output_tree` or vector-leaf fit. This proposal changes how the base trees share splits; it does not revive a rejected residual recipe or reuse a rejected weight.

XGBoost's official [3.4.1 vector-leaf introduction](https://xgboost.ai/2026/08/25/introducing-the-xgboost-vector-leaf-model) states that the histogram implementation supports CPU and CUDA. The [multi-output tutorial](https://xgboost.readthedocs.io/en/stable/tutorials/multioutput.html) documents binary multilabel targets and `multi_strategy="multi_output_tree"`. The existing hosted environment already pins XGBoost3.4.1. This feature remains experimental; documentation establishes API availability, not successful execution on our runtime. The [version3.4.1 native implementation](https://raw.githubusercontent.com/dmlc/xgboost/v3.4.1/src/tree/multi_target_tree_model.cc) uses the vector-leaf size field checked by the proposed smoke. Installed official Python tests also explicitly exercise binary multilabel classification with shared trees.

## Possible later falsification, not yet a sealed protocol

If the synthetic smoke and review pass, a proposed first real comparison would use exactly the existing664 features, original146899 sampled2021 training hours, six-day purge and depth6/lr0.05 recipe. All fourteen binary targets are trained together. No custom loss, residual offset, target-derived feature or reduced-gradient sketch is proposed. The future verifier must count the exact predeclared number of actual shared trees with14-output leaves, validate every native parameter and replay the full validation matrix.

Before any fold protocol exists, root noted the official article's caution about equal boosting rounds:600 shared trees have fourteen times fewer tree partitions than fourteen independent600-tree models. Although each shared leaf has fourteen output coefficients, the shared partitions can underfit; failure at600 rounds would reject that fixed recipe rather than vector models generally. After the actual synthetic capability check, a prospective bounded comparison of600 versus1800 shared rounds may be frozen, with depth6/lr0.05/rows/other parameters unchanged. The round count and blend weight must be selected jointly on2021 before a single locked2022 continuation, with a predeclared tie rule and resource budget. The1800-round arm changes capacity as well as partition sharing and must be described accordingly. No post-result round-count rescue is allowed. No such fold protocol or fit currently exists.

Current acceptedSHOP probabilities would be the anchor and the existing40%-sample scalar664 predictions the matched same-weight control. A separately frozen `[0,.1,.25,.5]` grid would prefer lower tied weights; any round-count tie rule must also be frozen before either fit. Only a positive2021 winner beating both anchor and matched control could proceed to independent lock review and a single locked2022 check. Direct base-model training needs no new OOF cache. These are reused development years, not a fresh holdout. This document does not authorize those fits or seal their protocol.

The sampled float32 feature table occupies about390MB; fourteen-output float32 gradients plus Hessians occupy about16.5MB before histograms and other allocations. Histogram storage and full feature construction can dominate those components. Actual runtime/peak memory are unknown; the scalar664 timing does not establish vector-leaf speed. A future bounded fold would require a measured memory guard and an explicit wall-time budget. Native model serialization and the existing private datasets offer a straightforward deployment path if the smoke passes, but the current per-generator verifier needs a separate reviewed vector-tree adaptation.

Queued fullsampleSHOP664, additive745 and the748 integer-cache experiment remain higher priority because their physical/input hypotheses already have direct evidence. Shared vector leaves are the next orthogonal learned branch after those queued jobs, not a reason to delay accepted final exports or physical-cache completion.
