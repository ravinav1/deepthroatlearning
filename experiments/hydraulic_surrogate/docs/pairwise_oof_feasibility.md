For this micro-AUC metric, positives and negatives must be compared across cases and generators. A query per case or per generator would omit relevant cross-group pairs. XGBoost documents `rank:pairwise` as unscaled pairwise logistic loss, with pairs formed within query groups; `rank:ndcg` instead applies an NDCG-derived scale. Its `mean` sampler and `topk` sampler also target different pair distributions. These facts support considering pooled uniform positive-negative pairs, rather than claiming NDCG directly optimizes this metric. [Official ranking documentation](https://xgboost.readthedocs.io/en/stable/tutorials/learning_to_rank.html).

The AUC optimization paper motivates consistent pairwise surrogates and a stochastic saddle-point method for squared loss. It is not evidence that a particular residual tree recipe will improve these data. [Liu et al.,2018](https://proceedings.mlr.press/v80/liu18g.html).

A discriminating test uses the same frozen80-tree/depth4/.03 residual model, base OOF logits and features for a pairwise objective and a BCE control, alongside identity. Uniform pairs over flattened positive and negative outputs need only score/index arrays;1million int64 positive-negative index pairs occupy16MB, with no pair-feature matrix. If pair loss is scaled by N/(2M), its balanced zero-margin expected row gradients and diagonal curvature match sum BCE. Pair curvature includes cross-row terms. Twice its diagonal is a valid positive-semidefinite Hessian majorizer: each pair contributes a positive multiple of[[1,1],[1,1]] to twice-diagonal minus true Hessian. This is a fixed conservative optimizer choice, not an exact Newton Hessian.
