# Independent canonical screen result audit

The prepared auditor accepts only a completed canonical115 v2 screen, the exact approved protocol and training review, and a separately hashed process-exit observation. It does not fit models. Actual execution needs the large local feature slot after the producer exits.

It independently reconstructs every saved training and screen feature row from the original 664 inputs in bounded blocks, using a separately stated generator-relative mapping. It verifies the original 122,304-hour sample, sampled training targets, all 360 screen targets and case/hour/unit order. The 14 categorical per-unit models and both pooled checkpoints must have the fixed native parameters and replay every screen row exactly in float64. The 700-tree checkpoint must equal the actual first 700 native trees of the 1,400-tree checkpoint.

The checker binds all source and artifact hashes, the prediction seal and label-opening chronology, and the two final observed resource checks. Independent isotonic projection and rank-sum AUC reconstruct all eight fixed blends, four matched controls, full-year and half-year scores, tie rules, six strict acceptance gates and the selected output. A failed selected candidate cannot be replaced by another grid entry. The original 2020 screen remains reused development evidence.

The exit observation schema is `canonical_pooled_process_exit_v1`: `status="passed"`, exact candidate-manifest and protocol hashes, `producer_pid`, `process_exited=true`, `launch_observed=true`, and `observed_launch_command` equal to the producer manifest's command string. Its exact command is `ps -p PID -o pid=,stat=,command=`, returning 1 with empty stdout/stderr. Its UTC timestamp must follow the finalized producer runtime. The observation is external; the auditor does not attempt to signal or stop the producer.

The command requires `--protocol`, `--protocol-sha256`, `--candidate-run`, `--candidate-manifest-sha256`, `--training-audit`, `--training-audit-sha256`, `--exit-observation`, `--exit-observation-sha256`, and a fresh `--run-id`. No actual candidate exists when these templates are prepared. Six focused synthetic tests cover independent feature remapping and signed zero, saved native synthetic checkpoint replay and corruption, selection/no-rescue, exit evidence, original target row ordering, safe paths and score tolerance.
