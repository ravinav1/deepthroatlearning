# Independent CUDA runner and returned-result review

Audit artifact: `artifacts/cuda-return-audit-001/manifest.json`. This review reads source and uses small synthetic fixtures only. It does not rebuild the 395-feature table, deserialize neural checkpoints, fit a model, access Kaggle, or establish GPU speed/accuracy.

The XGBoost runner, offline uv launcher and local selector were reviewed independently. The runner retains the fixed 600-round, 14-unit recipe; reconstructs the earlier sequential RNG samples and requires their exact NPY hashes; forbids validation-dependent stopping; and gates the separate 2022 command with a checksum-pinned 2021 selection lock before staging data. It requires a CUDA build, two visible devices, native `cuda:1` and `grow_gpu_hist` after execution, plus fresh saved-model prediction equality. These guards must pass the hosted synthetic smoke on the installed XGBoost version before a real run. Official references: [GPU use](https://xgboost.readthedocs.io/en/stable/gpu/index.html), [prediction](https://xgboost.readthedocs.io/en/stable/prediction.html), and [parameters](https://xgboost.readthedocs.io/en/stable/parameter.html).

Three initial XGBoost selector provenance gaps were corrected by its owner before packaging: checking anchor prediction bytes against the pinned anchor manifest before decoding; comparing returned chronological IDs with the protocol vectors; and checking the returned shared-loader checksum. The reviewed final code contains those fixes. The selector independently recomputes pooled AUC, uses the fixed global grid `[0, .1, .25, .5]` on 2021, selects the first maximum, and evaluates only zero plus the locked weight on 2022. Both-year strict improvement is separate from the `.998` migration gate. Its claims of GPU execution and checkpoint replay depend on the reviewed runner and its recorded native configurations; this audit did not execute XGBoost on a GPU.

The TCN returned-result selector verifies the exact seven-file allowlist and hashes before numeric decoding. It checks the fixed final epoch24, 24 complete training-case permutations, training-only normalizer ID scope and finite float64 statistics, the frozen feature formula specification, actual reported CUDA settings, and byte-identical saved replay predictions. Only the explicit `lp.cache_directory` portability field is canonicalized. It verifies the anchor prediction hash before decoding and exact OOF labels, case IDs and unit order. It recomputes raw and per-unit AUC locally, but does not claim local checkpoint inference or independently recomputed normalization statistics.

TCN 2022 processing validates the external 2021 lock and its explicit checksum before decoding the returned fold. The downloaded run must contain that identical lock. It evaluates only zero and the selected weight, accepting a positive weight only on strict improvement in both years. Its specified formula mixes the already-projected accepted anchor with raw TCN probabilities in float64 and applies the fixed Vinje projection afterward. That nested formula is explicit and is not confused with flattening all earlier raw component predictions.

Independent command: `.venv-ml/bin/python -m unittest tests.test_cuda_xgb tests.test_select_cuda_tcn_blend`. All 11 fixtures passed; unittest reported 0.141 seconds. Tests cover device fallback, sample reproduction, selection-lock binding, tampered anchor/checkpoint bytes, replay mismatch, held-out cases in normalization, repeated/missing epoch cases, changed formulas and restricted weight evaluation. The audit manifest preserves reviewed source hashes and package versions. The earlier shared staging/training-loader review remains `artifacts/cuda-tcn-audit-002/manifest.json`.

No blocking correctness finding remains in this reviewed source. Real returned fold verification and hosted XGBoost smoke are separate required executions. No result or leaderboard gain is inferred from these fixture passes.
