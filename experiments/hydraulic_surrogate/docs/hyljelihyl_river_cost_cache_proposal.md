# Proposed compact C features and all-input cache

This is preparation only. The broader unchanged 36-case diagnostic and its independent result audit precede a full-cache decision. The original twelve-case result is positive in aggregate but negative for one date block, so it does not establish a supervised or leaderboard gain. No cache or new fit is launched by this proposal.

Keep arm C's complete v2 mathematics unchanged. For an eventual all-input cache, use the existing frozen continuous SHOP arm A as the exact per-case reference and solve only C. B is the diagnostic isolation control; it does not need a new full cache to construct C-minus-A features. Every original feature column and byte in the accepted 664-column input remains the prefix. New features receive distinct names and never replace the accepted SHOP, LP, context or joint-plant predictors.

Proposed feature size is 62 columns, giving 726 total. For each of fourteen units, append four dimensionless fields: clipped C continuous state; `(Q_C-Q_A)/Qmin`; `(P_C-P_A)/Pmax`; and `(nu_A-nu_C)/(initial_first_segment_energy*(1+mean(abs(price))))`. Compute `nu=lambda_up-lambda_down` with each arm's own network indices. In particular, Kjela's C downstream is Hyljelihyl, while its A downstream is the old Vinje pool; blindly reusing one network index array would be wrong. All denominators are the same positive frozen initial-case values. Clipping state only removes accepted solver-tolerance excursions; retain raw state in physical proofs.

Append six shared hourly routing fields: C Hyljelihyl volume divided by 0.26 Mm³; C remaining-Vinje volume divided by 307.00 Mm³; C main-river flow divided by 40 m³/s; C Hyljelihyl bypass flow divided by 40 m³/s; C remaining-pool bypass to Vinjevatn divided by 40 m³/s; and `(lambda_remaining-lambda_Hyljelihyl)/(initial_first_segment_energy_Vinje_G1*(1+mean(abs(price))))`. Flow arrays are stored in Mm³ per hour, so divide by `0.0036*40`, not directly by 40. The breakpoint is a normalizer, not clipping or a hard cap. Do not include objective values, solver runtime, optimality status, labels or post-start observed reservoir states as predictors.

This feature list is a mechanistic proposal, not a grid. Freeze exact names/order, float32 conversion, formulas and hashes before any supervised use. Require all source and input identities, all 3647 cases, exact case/date/hour order, complete physical proofs and no missing/nonfinite fields. The loader rejects incomplete or substituted caches and verifies that the 664-column prefix remains identical in names, dtype and bytes. Independently reconstruct every feature from retained physical arrays before packaging.

The twelve-case diagnostic uses two fresh processes for every case/arm. About one second of Python startup dominates each approximately 0.1–0.3 second solve. A full C cache could use two long-lived, separately spawned single-thread workers, with each worker constructing a fresh SHOP matrix/solver instance for every case. Worker 1 and worker 2 each solve every case once. Both outputs must match in dtype, shape and literal bytes for the complete decoded result and every primal/dual array before the case receives an immutable complete receipt. Assign replicas to distinct persistent worker identities; do not let a generic pool accidentally run both replicas in one process.

This changes execution evidence: replicas are independent processes, but process state is shared across successive cases within each replica. Do not describe it as fresh-process-per-case replay. Before adopting it, freeze an input-only pilot on metadata-spaced cases spanning all 3647 inputs. Include the canonical 36 cases as direct controls and additional dates selected without labels. Run one worker in ascending order and the other in a separately fixed permutation. Require both workers' full bytes to match one another and the existing fresh-process C proofs for every compatible canonical case. Any order/history difference blocks this execution approach; no array averaging or silent relaxation of replay is allowed. Save PIDs, case order, native solver/package/thread identities and all failures.

Preserve the fixed 20-second native LP cap and physical tolerances for this pilot. There is no fallback or automatic retry. A non-optimal or resource-stopped case remains ineligible and its raw output is retained. A later proof-budget extension, if needed, is a separate recorded decision. Use a fresh current memory measurement before worker launch; leave at least 3 GiB measured headroom beyond existing jobs, and drain after active calls if system free memory falls below the declared threshold or swapouts increase. The running integer cache remains the resource priority.

Full-cache publication would be immutable per case and resumable only from verified complete receipts. Preserve the original twelve and broader 36 diagnostic proofs and their exact input compatibility; reuse them only when all physical inputs, formula/source identities and solve settings agree, with explicit provenance for their stronger fresh-process replay type. The aggregate cache becomes eligible only after all 3647 complete receipts, the compact feature archive and an independent physical/replay/feature audit pass. No partially completed feature archive may enter a trainer.

The current sample is too small to promise a full-cache duration. The 24 C workers average 0.272341 seconds after imports, with median 0.269515 and maximum 0.316494 seconds. A simple two-worker, two-replica extrapolation is 16.55 minutes for 3647 cases, excluding full-input preparation, process startup, serialization, aggregate audit and unseen tails. Fresh-process-per-case startup would substantially increase that figure. Maximum measured worker RSS across all arms is only 245.7 MB, so two persistent processes appear inexpensive relative to the four integer workers and the local LGB fit, but the all-input pilot must measure this. Report startup-inclusive wall time, solve time, longest cases and status distribution separately. Do not extrapolate from imported receipts as if they were new work.

Any learned test then uses the unchanged chronological selection rules and exact controls: accepted 664 prefix/anchor, a fixed C-feature addition, the original sample/model parameters, a predeclared 2021 blend grid, and only its locked 2022 evaluation. Passing a physical diagnostic does not bypass those gates. Model package, training, final export and public submission remain separate actions requiring the actual accepted evidence.
