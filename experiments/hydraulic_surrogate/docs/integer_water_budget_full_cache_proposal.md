## Exact model and scope

Use the existing `IntegerWaterBudgetLP` source unchanged. It makes only Hogga, Lio and Haukeli state variables binary, retains the other eleven fractional unit states, and jointly optimizes the original full network water balance. Retain every supplied minimum/maximum flow and power bound, initial head, piecewise curve, terminal value, startup/shutdown cost, reservoir constraint and routing link. Add no minimum run time, ramp limit, estimated initial state, cost adjustment or new fitted parameter.

Use all 3,647 supplied input cases in their frozen original order. Reuse the exact assembled inputs and continuous controls from the independently audited `lp-shop-full-001` cache. Reconstruct every input independently and compare it to those saved arrays before using it. The twelve completed diagnostic solutions remain canonical and are copied byte-for-byte, including their original proof files. Their new independent full-MILP replay is recorded separately.

Before any solve, freeze source files, package and solver versions, CPU architecture, thread controls, supplied data hashes, complete case IDs/dates, input/control manifest hashes, the diagnostic and independent audit hashes, feature formulas and exact prefix column names. A rejecting read guard permits only `Run No` and `starttime` from the commitment CSV. Feature building and solver scheduling never read targets or select cases by errors.

## Solver effort and explicit failures

The proposed first attempt is a 60-second MILP, followed by the current two 1-second fixed-state LP replay limits. Keep one HiGHS thread and the existing zero relative-gap target. Record solver status/message, incumbent availability, integer residual, node count, relative gap, scaled incumbent and dual bound, converted euro bound, conditional LP residual, all feasibility/slack checks and measured wall time.

For a time limit, preserve the complete failed attempt and any incumbent. A separately identified, predeclared 600-second retry may be scheduled solely on solver status, using the identical formulation and inputs. The solver interface has no warm start, so the retry is a fresh solve; the earlier work is still retained as evidence. A missing or unproven incumbent, invalid physical result, nonzero slack or failed LP replay cannot produce an accepted feature row. There is **no continuous-LP substitution, zero-row substitution or hidden fill value**. If the final bounded attempt remains unresolved, retain an explicitly incomplete cache and all successful cases for a future separately frozen proof continuation. No model loader accepts that incomplete cache.

A true formulation/feasibility error is not treated as a reason to increase time. Preserve it and stop cache acceptance pending investigation. Do not change a frozen source file to make a failure disappear.

## Reproducibility, immutable cases and resume

Prefer a full fresh MILP replay for every case, not only the conditional LP replay. Use a fresh solver instance/process under the same pinned environment, then compare the selected binary path and every feature-generating physical array bitwise. The first result is canonical. An alternative optimum can have the same objective but a different path or conditional dual; it is recorded as a replay failure rather than being averaged, silently chosen or claimed identical. Replay failures block acceptance until an independently reviewed deterministic tie policy exists. This is stricter and more expensive than merely reconstructing features from a single saved result.

Write each attempt to its own unique temporary directory, flush its files, then atomically publish an immutable directory containing the input/control identities, result, raw integer incumbent, proof, replay and checksums. A supervisor writes a new append-only journal record only after publication. Workers never share an output file and never overwrite an attempt. Completed case identities are keyed by the frozen mathematical protocol hash and case ID, not by worker assignment or completion time.

On interruption, preserve the original run manifest. A new run may import only complete, hash-verified case directories with the exact same mathematical protocol and source/data/solver identities. Failed attempts remain in the provenance chain. A crash during a write leaves an unpublished temporary attempt that is retained but cannot be mistaken for a completed case. The final cache manifest is created only after all 3,647 cases and replays satisfy the acceptance contract.

## Proposed 84 appended input-only columns

Append six fields per unit, in the established 14-unit order, yielding 84 columns and **748 columns overall**. All calculations use float64 saved arrays and convert the final features to float32. Preserve the existing exact first 664 columns, their dtypes, positions and values. The first 608 values and the current 56 continuous SHOP additions therefore remain unchanged.

| Field | Fixed formula and interpretation |
| --- | --- |
| State | Integer solution's raw unit state, clipped to `[0,1]` only within feasibility tolerance. Exactly three prescribed units are binary; the others remain fractional. |
| Flow change | `(Q_integer - Q_continuous_SHOP) / Qmin_initial`. |
| Power change | `(P_integer - P_continuous_SHOP) / Pmax_initial_case_feasible`. |
| Start | Saved nonnegative startup variable for transitions into hours 1–167; zero at hour 0, where the original model charges no transition. |
| Stop | Saved nonnegative shutdown variable with the same hour alignment and zero boundary convention. |
| Conditional margin change | `(nu_continuous_SHOP - nu_fixed_integer_path) / (E_initial_first_segment × (1 + mean(abs(case_price))))`, where `nu = lambda_up - lambda_down`, with sea dual zero. These are LP duals conditional on the chosen three integer paths, not global MILP marginal water values. |

This deliberately retains all fourteen units' responses because imposing integer states can move water and fractional schedules elsewhere in the network. It does not add case IDs, label-derived schedules, solver runtime, gaps, proof status or failed-incumbent indicators as predictors. The cache must pass completely before these features exist as an eligible modeling input.

Freeze the formulas before extraction. Test the transition-hour alignment and zero boundary, economic sign and common-dual cancellation, physical units, exact 664-column prefix preservation, and rejection of corrupted/misaligned/unproven cases. Reconstruct all appended features independently from saved raw results; verify no label access and exact ID/hour/unit ordering.

## Cost, workers and coexistence with OOF work

The twelve successful case wall times sum to 92.05 seconds: mean 7.67, median 5.04, 90th percentile 20.80, 95th percentile 22.60 and maximum 23.75 seconds. They include the conditional LP checks but are a small metadata-selected sample, not a reliable tail model. All twelve successful MILPs report one branch-and-bound node; the time is largely root-node work. A fixed node limit of one would not itself provide a predictable runtime or guarantee the same incumbent on harder cases, so it is not proposed as a silent substitute for proof.

One primary pass extrapolates to about 7.77 CPU-hours, or **3.89 hours with two one-thread workers**. A fresh MILP replay for every case roughly doubles that to **7.77 hours with two workers**. Allow approximately **8–12 hours** for the proposed full replay cache before difficult retries; this is a planning allowance, not a measured concurrency benchmark. The conservative first-pass-plus-replay cap is about 62.8 hours at two workers if every solve consumes its complete 60-second limit plus both LP checks. A 600-second retry increases that bound for each unresolved attempt; report the count and remaining estimate rather than hiding the added work.

The subsequent 24-case metadata-spaced pilot gives a better measured concurrency estimate. All 48 attempts ran in fresh spawned processes under two one-thread workers. All reached reported optimality, all 24 full result replays matched bitwise, both conditional LP solution/dual arrays were saved and identical, and all slacks were zero. The pilot took 137.31 seconds including process and input overhead. Mean attempt time was 4.65 seconds, median 1.70, 95th percentile 15.07 and maximum 16.33. Scaling actual elapsed time gives **5.80 hours for a full two-pass cache**; scaling solver time alone gives 4.71 hours. A **6–9 hour planning allowance** now appears more grounded than the earlier 8–12-hour estimate, but still does not characterize rare difficult cases or concurrent OOF contention. No pilot case used its 60-second cap. The pilot manifest SHA is `c7f4aea9b57a1f7272d721b59e2d989dcea2632cc2d7adef932802b6da561821`.

The machine exposes 12 logical CPUs. Two solver workers each use one HiGHS/BLAS thread, so concurrent two-thread OOF fitting requests roughly four compute threads in total. Contention and thermal effects are not measured by the isolated diagnostic. Start with exactly two solver workers only if the root agent's current resource allocation permits them; reduce concurrency without changing solver mathematics if needed. Report completed-case count, status distribution, CPU/wall time, RSS and revised ETA every minute, and summarize the first 100 newly solved cases to replace the twelve-case extrapolation with actual throughput.

The diagnostic process peaked near 0.79 GB RSS; the broader pilot's largest fresh worker used 0.90 GB. Budget approximately 1.8–2 GB for two solver processes, plus about 196 MB for the uncompressed 3,647 × 168 × 84 float32 feature array and supervisor/input overhead. The existing 664-feature construction separately measured 5.42 GB peak RSS; OOF model memory requires further headroom and must be observed, not inferred from that construction number. Avoid building the complete training matrix in either solver worker. Immutable result files averaged 31.9 KB per case in the diagnostic, approximately 116 MB per complete solution pass or 233 MB for primary plus replay, before input/proof/source files and the separately retained fixed-state LP arrays. Keep the compact cache and pinned source closure, without duplicating full feature matrices into every case.
