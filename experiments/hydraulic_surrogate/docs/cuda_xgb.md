# Portable full-unit GPU XGBoost protocol

This branch extends the earlier three-generator XGBoost experiment to all fourteen units using the exact same395 LP-v1 input features and exact baseline40% sampled training rows. The previous three-specialist candidate improved both development years at a joint50% replacement; that does not establish that a full fourteen-unit GPU model will improve them. No local or remote GPU model has been fitted by this preparation.

Requested learning parameters exactly match `xgb-lp-specialists-001`, except the explicit device:600 estimators, depth6, learning_rate0.05, min_child_weight20, reg_lambda4, reg_alpha0, max_bin128, subsample0.9, colsample_bytree0.9, colsample_bylevel1, colsample_bynode1, seed4173, n_jobs2, binary:logistic, histogram tree method, logloss evaluation metric, depthwise growth and max_delta_step0. No evaluation set, early stopping, parameter search, class weighting or additional learned normalization is used.

Use `cuda:1` so this branch can remain separate from the TCN's fixed `cuda:0`. Root observed a two-T4 Kaggle runtime with XGBoost3.4.1, Python3.13.15, NumPy2.1.3, pandas2.3.3, scikit-learn1.6.1 and uv0.13.5. The local reference used XGBoost3.2.0 on the CPU. GPU training and the library version differ; no exact-fit equivalence is claimed. Every actual installed version, XGBoost build configuration, driver/device report and full native learner configuration is captured. PyTorch CUDA availability does not establish XGBoost CUDA compatibility.

Official XGBoost documentation specifies the `device` option together with the histogram tree method for GPU training. This runner additionally checks the CUDA-enabled build, two visible NVIDIA devices, and the actual post-fit `cuda:1` device plus `grow_gpu_hist` updater; any CPU or alternate-device fallback is an error. A successful synthetic-only8-tree smoke must precede a real fit in an identical recorded environment. See [official GPU documentation](https://xgboost.readthedocs.io/en/stable/gpu/) and [official parameter definitions](https://github.com/dmlc/xgboost/blob/master/doc/parameter.rst).

The launcher creates an offline uv environment with `--system-site-packages` and the hosted `sys.executable`, reusing preinstalled CUDA libraries. It performs no installation, download or network request. Missing uv or incompatible installed CUDA packages cause an explicit failure. `scripts/launch_cuda_xgb.py` launches `scripts/train_cuda_xgb.py`; smoke is the default mode and must not receive competition data.

Reuse the sealed24-file private bundle and audited shared staging/feature loader from `scripts/train_cuda_tcn.py`. The loader verifies exact paths, sizes, hashes, source/data/cache provenance and395-column schema; it redacts target rows later than the explicitly selected year. It imports no PyTorch when used as a helper. The bundle is not modified or duplicated. Separate GPU year commands cannot train both years automatically.

The existing bundle omits sampled-row arrays. Reconstruct them by reproducing the original seed4173 RNG call sequence: draw2021 first, then draw2022 when requested, using the exact purged-case row arrays and40% fraction. Save toNPY and require byte SHA256 equality with the baseline manifest before fitting. Local metadata-only preflight reproduced both original arrays exactly:2021 has146,899 rows, SHA`a035a8f91ca56274e8f66852845dc40ca8d3fe32a70486b4756431c2fc6cd73a`;2022 has171,427 rows, SHA`41c226761eab936ae61e645ce292e0f35397bb43acf0501fc484187947c7adf8`. The authoritative exact hashes are in `artifacts/cuda-xgb-preflight-001/manifest.json` and the training protocol; no fallback resampling is allowed if the remote NumPy version differs in behavior.

After the2021 command, download its full output directory: manifest, raw OOF probabilities/labels/IDs/unit order, fourteen UBJ checkpoints, full native configs and runner/protocol/shared-loader snapshots. Each checkpoint must exactly replay all61,320 validation rows on the same GPU environment during training. Local verification checks every downloaded artifact hash, raw AUC, schema and anchor alignment. It does not claim bitwise inference equality across CPU/GPU or XGBoost versions.

The frozen anchor is `lp-joint-comparison-001`, selected before this branch:18.75% LP base,56.25% LP context,25% joint model, already Vinje-projected. It intentionally remains this declared anchor even though later608-feature experiments exist. Compare GPU weights`[0,.1,.25,.5]` with `project_vinje((1-w)*anchor_projected+w*gpu_raw)` in float64. Select maximum2021 pooled micro AUC, exact ties lower weight. `scripts/select_cuda_xgb_blend.py --year2021` creates an exclusive local lock linked to the protocol, anchor, downloaded run manifest and OOF hashes. The separate2022 GPU command requires that lock and its explicit SHA before reading inputs. Local2022 evaluation uses only zero and the locked weight, with a strict both-year improvement gate. No leaderboard-based tuning or per-unit selection occurs. Both years are reused development evidence.

The scripts do not perform a final-data fit, export, competition submission or repository transfer. Those steps require successful measured acceptance and root orchestration. The0.998 threshold on both validation years remains unmet by preparation alone.

Three small fixtures passed: actual-device/updater fallback rejection, correct sequential RNG consumption with exact NPY hash and no resampling fallback, and immutable2021 lock binding to the protocol/anchor.
