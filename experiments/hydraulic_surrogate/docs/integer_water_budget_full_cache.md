# Frozen execution contract for the full integer water-budget cache

Generate only input-derived physical results and 84 appended features for the original 3,647 case IDs. The mathematical model, three binary units and original 664 feature prefix are unchanged. Two spawned workers each use one solver/BLAS thread, and each submitted MILP attempt runs in a fresh process. The main process never builds the training feature matrix or reads target values.

Each of two independent replicas first gets a 60-second MILP and the existing two 1-second fixed-state LP checks. Only native MILP status 1 authorizes a separately recorded 600-second fresh retry. Failed, unproven, nonzero-slack or non-reproducible cases remain explicit; there is no relaxed-LP, zero or missing-row substitution. Both LP solution vectors and all residuals/marginals are retained. A complete case requires two proven MILP results equal in every saved array/scalar and exact equality between each pair of fixed-state LP outputs.

Preserve all twelve completed diagnostic result/proof files byte-for-byte as canonical evidence. Preserve all 24 audited timing-pilot case inputs and both attempt directories byte-for-byte. Their mathematical source, targets, bounds and physical inputs match the full cache. Pilot cases supply their two proven attempts without new solves. Diagnostic cases outside that pilot receive two fresh attempts, which must also equal the original canonical result in every field. Case 1 overlaps and must satisfy both histories.

Each new attempt writes into a unique temporary directory, then atomically publishes its immutable directory and proof. A case is published complete only after all files, physical checks, provenance, replay checks and feature formulas pass. Every completed case contains a source/protocol identity, input/control identities and a checksum of every payload. A new run may resume exact complete cases from an explicitly hashed prior manifest with the same protocol; original runs remain unchanged. Partial attempt directories stay in the old run. Complete immutable attempts can be reused by a future continuation, but this runner deliberately resumes only fully completed cases, avoiding ambiguous partial state.

The append-only journal and stdout report each completed attempt/case. The active aggregate manifest is checkpointed at every completion and is finalized separately; it cannot make an incomplete case eligible. Progress includes completed cases, failures, elapsed time and a measured ETA. A final features archive is written only if every case is accepted. The loader requires a complete cache, exact protocol/source/data/cache hashes, every case proof, finite features, exact ID/hour/unit/column alignment, and exact preservation of all 664 prefix values and dtypes.

The frozen feature specification is the one exported by `integer_water_budget_features.feature_specification()`: state, flow change, power change, start, stop and conditional economic-margin change, six fields for each of fourteen units. Exactly three states are binary; conditional LP duals are not global MILP water values. No solver-status, runtime, label, case-ID or fitted statistics become predictors.

The current audited pilot predicts about 5.8 hours for a complete two-pass cache with two workers, before rare 600-second retries or concurrent OOF contention. Retain every failed attempt and report actual tail behavior. Cache completion is not learned-model selection, final fitting or submission authorization.
