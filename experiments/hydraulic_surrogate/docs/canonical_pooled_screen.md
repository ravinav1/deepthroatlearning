# Canonical generator pooling: frozen early-2020 screen

The hypothesis is that one from-scratch binary classifier can share physical response curves across generators when each row describes the same generator-relative quantities. This differs from the rejected 80-tree residual models over 608 duplicated global columns and an existing model logit. It uses no prediction as an input and no class reweighting. Categorical unit and plant identifiers retain teacher-specific behavior; 14 global SHOP states and nine storage fills retain network context.

The adapter maps the immutable 664-column input schema into 115 columns: 53 common calendar/normalized-price fields, 19 own-generator fields, 16 own-plant fields, 23 shared state/storage fields and four identity descriptors. Unit and plant IDs are categorical; within-plant position and unit count are numeric. All values are cast directly to float32 without fitted normalization. Rows are case-hour then unit. Input-only feature calculations can inspect each supplied full-week horizon, including later hours in that same case; no labels are used by feature construction.

The screen uses exactly the original 122,304-hour third sequential seed-4173 sample from 1,820 cases dated 2015-01-01 through 2019-12-25. The existing 664 staged loader masks target dates from 2020 onward. All 14 labels for each sampled hour are retained, giving 1,712,256 pooled rows. The screen population is the original 360 cases from 2020-01-01 through 2020-12-25, including fixed January–June and July–December subsets. Its six-day purge excludes training horizons reaching the screen. The 2020 identity anchor is the already saved projected single608 full14 OOF predictor; no 2020 SHOP ensemble anchor exists. This is reused development data, not a new holdout.

Fourteen independent canonical controls each use the unchanged 350-tree, 31-leaf, learning-rate .06 LightGBM recipe and the same sampled hours. The pooled model uses that same recipe except for one 1,400-round trajectory, from which the 700- and 1,400-round checkpoints are saved. Both objectives are ordinary unweighted BCE. CPU threads are fixed at two. There is no early stopping or validation-set callback. Every checkpoint is replayed on every screen row before labels are decoded.

All fits, raw predictions and full checkpoint replays are sealed before opening the 2020 labels. For each checkpoint the fixed weights 0, .1, .25 and .5 blend raw probabilities with the projected identity anchor, followed by the existing float64 Vinje projection. Selection maximizes full-year micro AUC, breaking ties first toward fewer rounds and then lower weight. The selected positive weight must strictly beat both the identity anchor and the canonical per-unit control at that same weight on the full year and each half-year: six strict gates. A failed selected candidate cannot be replaced with the second-best candidate. No future year, final fit or submission is authorized by this screen alone.

The runner streams both train and screen canonical NPY files in bounded blocks, then frees the full 664 prefix before fitting. The synthetic timing study suggests roughly 18 minutes for the 1,400-round pooled trajectory and 3.5 minutes for the controls, but it does not measure real-data runtime. The prospective run allows 35 minutes observed wall time and 8 GiB observed peak RSS for the whole process, with a 6 GiB fit-memory target rather than an unverified guarantee. Entry requires at least 40% measured free memory; later checks require 20%. Checks occur between phases, each control and every 25 native boosting rounds; these are observational checks, not operating-system allocation or hard-time limits. Actual scheduling must preserve the one heavy-model slot and the running integer cache. A failed or resource-deferred run preserves its evidence and cannot score a partial set of models.

`scripts/prepare_canonical_pooled_screen.py` freezes metadata, source, exact samples, input bundles and prerequisites without decoding target values. `scripts/screen_canonical_pooled.py --preflight` verifies this closure without constructing features or fitting. Real execution additionally requires an externally pinned independent source/preflight audit. The original frozen 664 sources remain unchanged.
